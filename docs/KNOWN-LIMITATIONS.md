# 알려진 한계

## 공통

- 자동 업데이트 기능은 없습니다. 새 버전 파일을 직접 교체합니다.
- 현재 행동은 네 개의 고유 키프레임을 조합합니다. 더 부드러운 8~12개
  고유 프레임은 자산 제작량과 정체성 검수가 추가로 필요합니다.
- 소리는 포함하지 않습니다.
- 설정 동기화나 클라우드 기능은 없습니다.

## Windows

- 빌드 대상은 x86-64입니다. ARM64 Windows 네이티브 빌드는 별도 대상·검증이
  필요합니다.
- 공인 Authenticode 서명이 없으면 Smart App Control이 차단할 수 있습니다.
- `UpdateLayeredWindow` 기반이므로 매우 오래된 원격 데스크톱/그래픽 환경에서
  렌더링 성능 차이가 날 수 있습니다.

## macOS

- 최소 버전은 macOS 11이지만 로그인 자동 실행의 `SMAppService` 방식은
  macOS 13 이상에서만 제공합니다.
- Apple Developer ID 서명·공증 전에는 Gatekeeper 경고가 나타날 수 있습니다.
- AppKit을 동적 Objective-C 런타임 호출로 사용합니다. 크로스 컴파일에는
  유리하지만 일반 Objective-C/Swift 프로젝트보다 호출형 수정 난도가 높습니다.
- 소스 환경에서는 macOS 실제 GUI를 실행할 수 없으므로 실제 Mac 스모크
  테스트가 릴리스 승인 조건입니다.

## 호환성 변경 시

Windows SDK, Zig, macOS 런타임 정책이 바뀌면 빌드는 성공해도 실제 OS 동작이
달라질 수 있습니다. 컴파일 성공과 운영체제 정책 통과를 같은 것으로 보지
마세요.
